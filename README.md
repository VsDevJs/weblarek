# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

#### Интерфейсы: IBuyer - покупатель и IProduct - Товар

Интерфейсы покупателя и продукта являются контрактами для других частей программы. Они описывают возможность взаимодействия и получения данных в экземлярах классов, основанных на них В нашей архитектуре интерфейс IBuyer применяется в классах 'MainCatalog' и 'BasketProduct', а IProduct в классе 'BuyerStore', описание которых декларировано ниже

Поля интрефейса IBuyer:
`payment:TPayment` - Вариант оплаты для покупателя 
`email: string` - обязательное поле с емейлом покупателя, которое является обязательным и блокирует дальнейшие шаг оформления, если нзаполнено и не прошло валидацию
`phone:string` - обязательное поле с номером телефона покупателя с аналогичным требованием, как у email, для перехода к следующемшагу оформления
`address:string` - обязательное поле с адресом покупателя для перехода к следующему шагу оформления

Поля интрефейса IProduct:
`id:string` - id продукта
`description: string` - Подробное описание товара, которое используется в карточке открытой в модальном окне    
`image: string` - Название картинки товара
`title:string` - кракое описание товара
`category:string` - категория товара
`price: number | null` - Прайс товара

#### Интерфейс IProductResponse
Интерфейс который описывает шаблон для отправки данных для формирования заказа. Является производным от IBuyer
`payment` - типом поля является TPayment описаный ранее
`items` - Массив c id товаров с типом string 

#### Интерфейс IOrderResponse
Интерфейс, который описывает, возвращаемый результат после формирования заказа
`id` - id товара
`total` - Сумма заказа

#### Интерфейс IRequestOrder
Интрефейс получения данных с сервера. Расширен от IBuyer, поля которого описаны выше
`total` - номер заказа
`items: string[]` - массив товаров с типизацией IProduct, описанной ранее

#### Интерфейс TFormErrors
Интерфейс получения данных с сервера. Использует ключи IBuyer, значением которых являются валидирующие поля функции

#### ICard – базовая карточка товара
Тип, который используется для отображения карточки с ценой и названием

Поля:
`title` – Название товара, которое отображается в карточке
`price` – Цена товара, выводится рядом с названием

#### ICardByCatalog – карточка для каталога
Тип, используемый для рендера товаров в общем списке (каталоге)

Поля:
`image` – картинка товара
`category` - категория товара

#### ICardAction – действия карточки
Интерфейс для задания действий, которые можно повесить, например, на карточку товара.

Поля:
`onClick?: () => void` – функция, вызываемая при клике на карточку. Является опциональной

#### ICardBasket – карточка товара в корзине
Тип, используемый при отображении товара в корзине

Поля:
`id` – уникальный идентификатор товара (string)

#### ICardPreview – карточка в превью заказа
Используется при отображении подробной информации о товаре в модалке перед заказом
Здесь содержится описание, категория и фото

Поля:
`description` – описание товара
`category` – категория
`image` – метод

#### FormEventPayload
данные, передаваемые при открытии формы

Поля:
`target` – элемент (например, кнопка), по которому произошёл клик
`element` – сама форма, которая была открыта

### Модели данных

#### Класс MainCatalog
Является моделью данных, который хранит массив товаров и выбранную карточку на главной странице сайта
Имеет несколько методов для сохранения состояний и предоставления значений этих полей
Класс имеет расширерине `t extends {id:string}` для корректной отработки метода getIDProduct

Конструктор:  
`constructor(private listProduct: IProduct[])` - Конструктор принимает параметр listProduct, который является приватным поскольку не требуется производные классы во избежания нарушения принципа одного источника данных

Поля класса: 
`listProduct:IProduct[]` - Хранит массив товаров. Автоматически создаётся через параметр конструктора

`detailedProduct` - Свойство для хранения товара, выбранного для подробного отображения. Сохраняется значение через метод detaileProduct

Методы класса:  
`getlistProduct():T[]` - Метод является геттером. Необходим для получения массива товаров из поля _listProduct
`setListProduct(newList:T[])` - Метод является сеттером. Необходим для сохранение массива товаров
`setDetaileProduct` - Метод для сохранения товара для подробного отображения
`getDetaileProduct(id:string)` - Получение товара для подробного отображения
`getProductById(id:string):T | undefined` - получение товара по его id. Проверяет является ли _listProduct массивом и ищёт по полученному id совпадение с id объекта. Используется в методе detaileProduct в качестве получения продукта для проверки на наличие его в массиве

#### Класс BasketProduct
Класс,который является моделью данных, необходимая для хранения информации, связанной с оформлением заказа
Он предоставляет данные из корзины, которые используются для отображения состояния функциональной кнопки товара («Добавить в корзину» или «Удалить»), а также для последующего шага - "оформления заказа"

Поля класса: 
`private listProduct:IProduct[]` - хранит массив товаров для покупки, выбранных покупателем

Методы класса:
`getlistProduct():T[]` - метод для получения массива товаров, которые находятся в корзине. Если ничего не добавили в него, то возвращает пустой массив
`addProduct(product:T):void` - Добавляет товар, который был получен в параметре, в массив корзины _listProduct + 
`deleteProduct(product:T):void` - Удаление товара, полученного в параметре из массива корзины _listProduct
`clearBasket()` - Полная очистка корзины, соответственно очищается массив _listProduct
`calculatePrice()` - Получение стоимости всех товаров в корзине. Расчет происходит, если товаров в массиве _listProduct больше 0
`countProduct() ` - Метод, который считает количество товаров в корзине
`existenceProduct(id:string):boolean` - Проверка наличия товара в корзине по его id, полученного в параметр метода. Возвращает true, если продукт присутствует в массиве и напротив - false, если товар отсутствует. Метод используется для логики проверки в методах: deleteProduct и addProduct

#### Класс Buyer

Модель содержит информацию о покупателе, такую как контактные и платёжные данные
Эти данные необходимы для оформления и оплаты заказа, а также используются при создании сущности заказа и в дальнейшей логике программы

Конструктор:
`constructor (private payment: IBuyer[payment] = '',`
  `private email: string = '',`
  `private email: string = '',`
  `private phone: string = '',`
  `private address: string = '') {}`
Конструктор класса buyer предназначен для инициализации объекта покупателя с базовыми полями.
Все поля опциональны – при отсутствии значений будут использованы пустые строки по умолчанию.

Поля класса: 
`payment` - Содержит вид оплаты, выбранный покупателем
`address` - содержит адрес покупателя
`email` - email покупателя
`phone` - телефон покупателя

Методы класса:
`setBuyerData(form:Partial<IBuyer>)` — метод для обновления текущего экземпляра на основе данных формы.Принимает объект с частичным или полным набором свойств, соответствующих полям класса, и обновляет значения только тех полей, в которых произошли изменения
`getBuyerData()` - Метод, который выводит значения опциональных полей payment, address, email, phone
`validate()` - Метод валидации формы. Возвращает объект с ключами в виде полей класса, в которых указан результат валидации поля: true для валидных полей, строка ошибки — для невалидных
`clear(): void` - Метод очистки полей

### Слой Представления

#### Калсс Card<T>
Класс, который отвечает за отображение карточки товара
Расширяет компонент Component и работает с типом T, в который включены title и price.

Этот класс рендерит название товара и цену в HTML-элемент карточки

Поля:
`cardTitle` – элемент, в который вставляется название товара
`cardPrice` – элемент, в который вставляется цена

Методы:
`set title(val: string)` – устанавливает текст названия в карточке
`set price(val: number | null)` – вставляет цену, если есть. Если цены нет, то вставляется текст 'Бесценно'

#### Класс CardBasket – карточка товара в корзине
Класс, который отвечает за отображение товара в корзине пользователя
Расширяет Card<ICardBasket>. Умеет показывать title, price и ещё кое-что добавляет поверх

Поля:
`itemIndex` – элемент, где отображается номер товара в списке
`buttonDelete` – кнопка для удаления товара из корзины
Конструктор:
При создании карточки можно передать объект с действиями:
Если есть actions.onClick, то кнопка удаления подпишется на клик, и при нажатии будет исполняться эта функция

Сеттеры:
`set id(val: number)` – устанавливает номер товара в списке

#### Класс CardByCatalog – карточка товара в каталоге
Класс для отображения товара на главной странице или в общем каталоге
Наследуется от Card<ICardByCatalog>

Поля:
`cardImg` – элемент картинки товара
`cardCategory` – элемент, в который вставляется название категории
Конструктор:
При создании карточки можно передать actions.onClick.
Если такая функция есть — она навешивается на клик по всей карточке.

Сеттеры:
`set category(val: string)` –
Вставляет название категории в элемент card__category,
а также переключает CSS-классы в зависимости от типа категории (используется categoryMap).

`set image(val: string)` –
Подставляет изображение через метод `setImage()` (картинка + alt с названием товара).


#### Класс CardPreview – карточка подробного просмотра товара
Класс, который отображает товар в большом виде, внутри модального окна
Наследуется от Card<ICardPreview>, так что помимо `title и price`, сюда добавлены `image, description и category`.

Поля:
`cardButton` – кнопка действия ("Добавить" / "Удалить" / "Недоступно")
`cardDescription` – блок с подробным описанием товара
`cardImage` – картинка товара
`cardCategory` – надпись с категорией + фон в зависимости от категории

Конструктор:
Если переданы действия `(actions.onClick)`, то навешивается обработчик на кнопку.

Методы и сеттеры:

`set description(val: string)` –
Вставляет описание товара в карточку

`set category(val: string)` –
Записывает название категории и меняет фон с помощью `categoryMap`, как в других карточках

`set image(val: string)` –
Устанавливает изображение и alt-текст с названием товара через встроенный setImage

`UpdateCardButton(val: boolean | null)` –
Обновляет текст и состояние кнопки
Если null → кнопка отключается, пишется "Недоступно"
Если true → "Удалить из корзины"
Если false → "Добавить в корзину"


#### Класс Gallery – компонент каталога товаров
Этот класс отвечает за отображение списка карточек товаров на главной странице (в каталоге)
Расширяет базовый Component<IGalleryData> и управляет блоком с классом .gallery

Поля:
`catalogElement` – DOM-элемент, куда добавляются карточки товаров
Он ищется внутри переданного контейнера по селектору .gallery

Сеттеры:
`set catalog(items: HTMLElement[])` –
Принимает массив карточек и полностью заменяет содержимое каталога этими карточками
То есть старые карточки удаляются, и на их место вставляются новые


#### Класс: Header компонент шапки сайта
Класс управляет отображением и поведением шапки, показывает количество товаров в корзине и обрабатывает нажатие на иконку корзины.
Наследуется от Component<IHeaderData>.

Поля:
`basketCounter` – элемент, в котором отображается текущее количество товаров в корзине
`basketButton` – кнопка-иконка корзины в хедере
Конструктор:
При создании класса:
Находит элементы `.header__basket-counter и .header__basket` внутри контейнера
Добавляет обработчик на click по кнопке корзины
При клике эмитится событие `basket:open` чтобы показать модальное окно с корзиной

Сеттеры:

#### Класс: Modalкомпонент модального окна
Класс управляет логикой показа и скрытия модального окна
Расширяет базовый Component<IModal> и работает с элементами типа .modal, .modal__close и .modal__content

Поля:
`modalClose` – кнопка закрытия модального окна (крестик)
`_modalContent` – блок, в который вставляется содержимое модалки
Конструктор:
Находит элементы модалки `(.modal__close, .modal__content)` внутри контейнера
Навешивает обработчик `click` на контейнер:
Если пользователь нажал:
либо на фон вокруг модалки (.modal),
либо на сам крестик, вызывается метод `closeModale()` для закрытия окна

Сеттеры:
`set modalContent(val: HTMLElement)` –
Заменяет содержимое модального окна на переданный элемент (val)
Используется при открытии карточки, формы или корзины


#### Класс OrderSuccess компонент окна успешного оформления заказа
Класс отвечает за отображение сообщения после того, как заказ был оформлен
Показывает сколько «синапсов» списано и обрабатывает закрытие этого сообщения
Наследуется от Component<IOrderSuccess>

Поля:

`orderButton` – кнопка «Закрыть» внутри окна

Списано 200 синапсов,

#### FormBase – базовая логика любой формы
От которого можно наследовать формы Управляет кнопкой отправки, проверкой на ошибки и переключением активности кнопки.
Наследуется от Component<void>, так как не требует входных данных в render()

Поля:
`buttonForm` – кнопка отправки формы (ищется по button[type="submit"])
`formErrors` – элемент, в котором отображаются ошибки формы
Конструктор:
Инициализирует нужные элементы в контейнере
Добавляет обработчик на клик по кнопке формы
При нажатии вызывает событие 'form:next', и передаёт:
`target` – кнопку, по которой нажали
`element` – саму форму
Это позволяет внешней логике (презентеру) понять, что пользователь хочет перейти к следующему шагу

Методы:
`setError(val: string[])` –
Устанавливает список ошибок:

Если ошибок нет кнопка включена (disabled = false)
Если ошибки есть → кнопка выключается (disabled = true)
Текст ошибки отображается в form__errors
`buttonFormStatus(val: boolean)` –
Меняет активность кнопки вручную:
true кнопка выключается
false кнопка активна
